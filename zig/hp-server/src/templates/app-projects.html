SQLite database

Open SQL runner

Per-project SQLite at ~/data/dbs/<id>.db, mode 0600. Auto-created on first connect. No size limit beyond available phone storage.

Already exposed to your runtime via:

DATABASE_URL=file:<auto-injected>
ROFI_DB_PATH=<auto-injected>
Code snippets
Node + better-sqlite3
import Database from 'better-sqlite3';
const db = new Database(process.env.ROFI_DB_PATH);
db.exec('CREATE TABLE IF NOT EXISTS notes (id INTEGER PRIMARY KEY, body TEXT)');
const rows = db.prepare('SELECT * FROM notes').all();
Node + Drizzle ORM
import { drizzle } from 'drizzle-orm/better-sqlite3';
import Database from 'better-sqlite3';
const db = drizzle(new Database(process.env.ROFI_DB_PATH));
// DATABASE_URL also works for drizzle-kit migrations
Python + sqlite3
import os, sqlite3
con = sqlite3.connect(os.environ['ROFI_DB_PATH'])
con.execute('CREATE TABLE IF NOT EXISTS notes (id INTEGER PRIMARY KEY, body TEXT)')
con.commit()
Python + SQLAlchemy
from sqlalchemy import create_engine
import os
engine = create_engine(os.environ['DATABASE_URL'])  # file:<path>

Auth-as-a-Service

Three endpoints already mounted on your subdomain. JWT signed with a per-project key derived from a per-install pepper - so projects can never sign each other's tokens. 7-day TTL.

POST /auth/signup    { email, password }
POST /auth/login     { email, password }   -> { token }
GET  /auth/verify    Authorization: Bearer <token>
Code snippet (frontend) 
// Signup
const r = await fetch('/auth/signup', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password }),
});
const { token } = await r.json();
localStorage.setItem('jwt', token);

// Make authenticated requests later
fetch('/auth/verify', {
  headers: { Authorization: 'Bearer ' + localStorage.getItem('jwt') },
});

Secrets & environment

Variables you set in the Env vars tab are AES-256-GCM-encrypted on disk and decrypted only into your running process. Plus we always inject:

PORT=<allocated>            # bind to this!
HOST=127.0.0.1
NODE_ENV=production
ROFI_PROJECT_ID=<your id>
ROFI_SUBDOMAIN=<your subdomain>
ROFI_PUBLIC_URL=https://<sub>.rofihosted.space
ROFI_DB_PATH=<sqlite path>
DATABASE_URL=file:<sqlite path>
ROFI_AUTH_BASE=/auth

Any DATABASE_URL you set via secrets overrides the auto-injected SQLite. Useful if you'd rather use a hosted Postgres (Supabase, Turso, Neon, etc).

Scheduled tasks

Use the Tasks tab to define cron-like jobs that run inside your project's environment. Same env vars, same DB, runs as a child of your project.

schedule: every 1h  command: node scripts/cleanup.js
schedule: 0 9 * * *  command: python3 generate_report.py

Want Postgres / Redis / vector DB?

A phone with 6 GB of RAM can't run a Postgres server for every tenant. Use a hosted free tier and put the connection string in your Env vars:

  • Supabase - Postgres + Auth, 500 MB free
  • Turso - SQLite at the edge, 9 GB free
  • Neon - serverless Postgres, 0.5 GB free
  • Upstash - Redis + Vector, free tier

Set DATABASE_URL=postgres://... in Env vars and it'll override the bundled SQLite for the next deploy. Most ORMs (Drizzle, Prisma, SQLAlchemy) work the same way against either.
